    MAC Address Formatter for Single Addresses and Bulk Lists

    A MAC (Media Access Control) address is a 48-bit identifier assigned to a network interface. It is used at Layer 2 (the Data Link layer) of the OSI model to deliver frames inside a broadcast domain. The same 48 bits are written differently by different operating systems and vendors, so engineers constantly convert between notations when they move data between switches, firewalls, NAC systems, DHCP servers and spreadsheets.

    This page covers both cases. Single mode converts one address live as you type, shows every notation at once, explains the address bits, and gives you a shareable link. Bulk mode converts a whole list of thousands of addresses in one pass to a single target format and reports every invalid line with its line number, so you can fix the source data.

    How to Use This Tool

    1. One address: stay on Single MAC, type or paste a MAC in any format. All formats appear instantly; click one to copy it, or pick a preferred format and click Copy Result. Copy link copies a URL that reopens the same conversion.
    2. Many addresses: switch to Bulk, paste one MAC per line (mixed formats and full CLI output lines are fine) and choose the output format. The output refreshes as you type, or click Format All.
    3. Check the statistics and the Invalid Lines list, then click Copy All or Download .txt.

    Output Formats

    • Colon — AA:BB:CC:DD:EE:FF / aa:bb:cc:dd:ee:ff. Linux and macOS (ip link, ifconfig), most firewalls and RADIUS attributes.
    • Hyphen — AA-BB-CC-DD-EE-FF / aa-bb-cc-dd-ee-ff. Windows (ipconfig /all, getmac) and the IEEE canonical form.
    • Cisco dot notation — aabb.ccdd.eeff. Cisco IOS and IOS XE (show mac address-table, show arp).
    • No separator — AABBCCDDEEFF / aabbccddeeff. Databases, APIs and MAC authentication bypass user names.

    Supported Input (Auto-detected)

    Each input line is scanned for the first MAC-shaped token: six colon- or hyphen-separated byte pairs, three dot-separated groups of four hex digits, or 12 raw hex digits (an 0x prefix is accepted). Upper and lower case are both accepted. Text around the token, such as VLAN IDs, IP addresses, interface names or CSV columns, is ignored. A line that consists only of hex digits and separators (for example AA BB CC DD EE FF) is accepted if it holds exactly 12 hex digits. Anything else, such as 11 or 13 digits or a letter outside A–F, is reported as invalid with the reason.

    Real-World Bulk Workflows

    • Cisco switch MAC table — paste show mac address-table output directly and convert the Cisco dot-notation MACs to colon format for a firewall or NAC import.
    • DHCP leases and logs — normalize MACs from lease files before importing them into a CMDB or an IPAM system.
    • 802.1X / MAB allow-lists — build MAC lists in the exact format your RADIUS or NAC server expects, often raw lowercase or hyphen uppercase.
    • Wireless controller exports — unify client MAC lists from different AP vendors and remove duplicates.

    Understanding the MAC Address Structure

    • OUI (bytes 1–3) — Organizationally Unique Identifier assigned by the IEEE to a manufacturer. It identifies the vendor (for example 00:50:56 = VMware).
    • Device part (bytes 4–6) — assigned by the manufacturer to make each interface unique.
    • I/G bit — the least-significant bit of the first byte. 0 = unicast, 1 = multicast (group). FF:FF:FF:FF:FF:FF is the broadcast address.
    • U/L bit — the second-least-significant bit of the first byte. 0 = globally unique (IEEE OUI), 1 = locally administered, as used by many VMs, containers and randomized Wi-Fi MACs. A second hex digit of 2, 6, A or E indicates a locally administered unicast address.
