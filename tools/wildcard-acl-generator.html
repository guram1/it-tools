What a wildcard mask is and why vendors differ

            
A wildcard mask (inverse mask) tells a Cisco ACL which address bits to compare. A 0 bit means "must match", a 1 bit means "don't care". For a contiguous prefix it is simply the bitwise NOT of the subnet mask: /24 = mask 255.255.255.0 = wildcard 0.0.0.255; /22 = 255.255.252.0 = 0.0.3.255. IOS also has two shorthands: any stands for 0.0.0.0 255.255.255.255 and host A.B.C.D for A.B.C.D 0.0.0.0. The generator emits those forms for /0 and /32.

            
Other platforms do not use wildcards for the same job. Cisco ip prefix-list and Junos prefix-list take prefix/length. FortiOS config firewall address takes an address and a normal subnet mask. One prefix list therefore has to be written three ways, and getting that wrong by hand is how most ACL outages start. This page writes all of them from one input.


            
How the generator works

            
    
                
  1. Parse. Each line can be CIDR, IP mask, IP wildcard, a bare IP, host IP or any. Masks and wildcards are told apart by bit pattern: ones from the left make a subnet mask, ones from the right make a wildcard. 0.0.0.0 and 255.255.255.255 are valid as both, so they are resolved Cisco-style: after 0.0.0.0 they mean any, after any other address they mean a host. If host bits are set (10.1.2.3/24), the entry is normalised to 10.1.2.0/24 and a warning is shown.
    2. 
                
  2. De-duplicate, optionally aggregate. Exact duplicates are always dropped. With Aggregate first on, the prefixes are converted to numeric ranges, merged where they overlap or touch, and split back into the minimal set of aligned CIDR blocks. Without it, the original order is kept and any prefix that sits inside another one is reported as redundant.
    3. 
                
  3. Generate. Sequence numbers start at your value and increase by your step. The same numbers are used for the ACL and the prefix-list, so entries line up when you compare them.
    4. 
            


            
Worked example

            
The prefilled sample contains seven lines. 10.10.0.0/24, 10.10.1.0/24 and 10.10.2.0/23 together are exactly 10.10.0.0–10.10.3.255, which is one aligned /22. 10.10.1.128/25 is already inside 10.10.1.0/24. 198.51.100.0 255.255.255.128 (mask form) and 198.51.100.128 0.0.0.127 (wildcard form) are the two halves of 198.51.100.0/24. With aggregation on, the output is three entries:

            
ip access-list standard MGMT-NETS
 10 permit 10.10.0.0 0.0.3.255
 20 permit host 192.0.2.10
 30 permit 198.51.100.0 0.0.0.255

            
The Junos filter references the list with from source-prefix-list MGMT-NETS. FortiOS gets three address objects (set subnet 10.10.0.0 255.255.252.0 and so on) and one addrgrp. Seven lines of intent became three entries on each platform. Every original address is still matched, and no extra address is.


            
Vendor caveats worth knowing

            
    
                
  • Cisco implicit deny. Named ACLs and prefix-lists both end in an implicit deny. A list made only of deny lines blocks everything. Tick Append catch-all to add permit any, permit ip any any or permit 0.0.0.0/0 le 32 as the last line.
    • 
                
  • Cisco sequence numbers. Named ACL entries can be numbered up to 2147483647. If you omit the numbers, IOS starts at 10 and steps by 10. Prefix-list seq runs from 1 to 4294967294 and defaults to 5, stepping by 5. Leave gaps so you can insert entries later. ACLs can be renumbered with ip access-list resequence.
    • 
                
  • Prefix-list ge/le rules. IOS requires len < ge ≤ le ≤ 32. With ge alone the upper bound is /32. The tool applies your ge/le to every prefix: a ge that is not longer than a given prefix is rewritten to the equivalent range, and an le shorter than the prefix is reported and the entry is written as an exact match.
    • 
                
  • Junos prefix-lists match exactly in policy. In a policy-statement, from prefix-list only matches routes that are identical to a list entry. For length ranges the generator switches to route-filter with exact, upto /N, orlonger or prefix-length-range /A-/B. In a firewall filter, source-prefix-list matches any packet address inside the listed prefixes, which is what you want for an ACL. Juniper documents a limit of 85,325 prefixes per prefix-list.
    • 
                
  • Junos implicit discard. A packet that matches no term in a firewall filter is discarded. A discard term without a later then accept term therefore drops all traffic on that interface, including routing-protocol traffic if you apply the filter to lo0.
    • 
                
  • FortiOS objects have no action. Permit or deny lives in config firewall policy. Address and address-group names can be up to 79 characters on FortiOS 7.4, and generated object names are truncated to fit. set member replaces the whole member list of an existing group; use append member to add to it.
    • 
            


            
Common mistakes this tool catches

            
    
                
  • A subnet mask where a wildcard belongs. In an IOS ACL, permit 10.0.0.0 255.255.255.0 does not mean 10.0.0.0/24. Read as a wildcard it says "ignore the first three octets, the last octet must be 0", so it matches every x.y.z.0 address. Paste such a line here and the tool reads 255.255.255.0 as a subnet mask and writes the correct wildcard.
    • 
                
  • A wildcard where a subnet mask belongs. The reverse happens on FortiGate: set subnet 10.1.1.0 0.0.0.255 does not create the /24 you meant. The FortiOS output always uses real masks.
    • 
                
  • Discontiguous wildcards. IOS ACLs accept wildcards such as 0.0.254.255, which match a bit pattern rather than a prefix. They cannot be expressed as CIDR, so the list input rejects them. The converter below the outputs explains them and counts the addresses they match.
    • 
                
  • Aggregating a route filter. Collapsing 10.0.0.0/24 and 10.0.1.0/24 into 10.0.0.0/23 is safe for packet ACLs. In a BGP prefix-list it stops matching the two /24 routes unless you add le 24. The tool warns whenever aggregation changed the set.
    • 
                
  • /31 and /32 math. The converter treats a /31 as two usable addresses (RFC 3021 point-to-point links) and a /32 as a single host.
    • 
            

            
Always review generated config before you apply it. Check with show ip access-lists NAME / show ip prefix-list NAME on IOS, show | compare followed by commit check or commit confirmed on Junos, and show firewall addrgrp NAME on FortiOS. Apply ACLs to management planes and routing sessions in a change window, and keep a rollback ready.
